# NEXUS NEST makerthon integration

## Existing event API contract

The existing `/api/v1/calls` API carries both hardware events and web teacher calls. No separate `/events` endpoint is needed. Call state values stay lowercase: `requested` → `accepted` → `responding` → `completed`.

| Purpose | Method and path |
| --- | --- |
| Health | `GET /api/health` |
| Demo room and its `id` | `GET /api/v1/demo/room` |
| Create cry or teacher-call event | `POST /api/v1/calls` |
| List latest calls and event history | `GET /api/v1/calls` |
| Accept, respond, complete | `POST /api/v1/calls/{call_id}/transition` |

Create body fields: `room_id` (required string), `room_name` (required string), `event_type` (`CRY_DETECTED` or `TEACHER_CALL`; defaults to `TEACHER_CALL`), `severity` (`WARNING` or `DANGER`; defaults to `WARNING`), `source` (defaults to `web`), optional `requester`, and optional `event_id` (unique ID generated by the sender). Retries with the same `source` + `event_id` return the existing snapshot without creating a second event. This deduplication response remains HTTP 201 and does not currently include a separate duplicate flag. A separate unfinished call for the same room returns HTTP 409.

Example request:

```json
{
  "room_id": "demo-classroom",
  "room_name": "NEST 데모 교실",
  "event_type": "CRY_DETECTED",
  "severity": "WARNING",
  "source": "mac-microphone",
  "event_id": "mac-20261024-0001"
}
```

Successful create returns HTTP 201 and the full snapshot. The new call appears under `calls`, with its generated server `id`, `source_event_id` equal to the sender's `event_id`, and status `requested`:

```json
{
  "calls": [{
    "id": "<server-generated UUID>",
    "room_id": "demo-classroom",
    "room_name": "NEST 데모 교실",
    "event_type": "CRY_DETECTED",
    "severity": "WARNING",
    "source": "mac-microphone",
    "source_event_id": "mac-20261024-0001",
    "status": "requested"
  }],
  "events": [{"type": "requested"}],
  "summary": {"requested": 1, "active": 0, "completed": 0, "total": 1},
  "demo_mode": false
}
```

Error responses use FastAPI's JSON `{"detail": ...}` shape. HTTP 409 means an unfinished call already exists in that room or a state transition is invalid. HTTP 422 means required or constrained fields are invalid; `detail` is then a list of field validation errors. A missing call ID on transition returns HTTP 404.

Transitions use the server-generated call `id`, not the sender's `event_id`:

```json
{"action":"accept","actor":"원장"}
```

Send `respond` and then `complete` to the same transition path. `GET /api/v1/calls` is the state/history query.

## Windows server and MacBook request

From `C:\Users\baru_\nexus-nest\apps\api` on Windows, use the Python 3.10.5 interpreter already running the current API. (The `python` shim in this Windows shell currently has no selected pyenv version.) Install the existing pinned requirements and start port 8000 on the LAN interface:

```powershell
$py = 'C:\Users\baru_\scoop\apps\pyenv\current\pyenv-win\versions\3.10.5\python.exe'
& $py -m pip install -r requirements.txt
& $py -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Find the Windows Wi-Fi IPv4 address with `ipconfig`. The current machine reports `192.168.184.67`; on the Mac, replace that value if it changes. Both devices must be on a network that allows peer connections, and Windows Firewall must allow inbound TCP 8000. The API process that was running during verification listened only on `127.0.0.1:8000`; stop it and restart with `--host 0.0.0.0` before expecting Mac access.

```bash
curl -i -X POST 'http://192.168.0.10:8000/api/v1/calls' \
  -H 'Content-Type: application/json' \
  -d '{"room_id":"demo-classroom","room_name":"NEST 데모 교실","event_type":"CRY_DETECTED","severity":"WARNING","source":"mac-microphone","event_id":"mac-20261024-0001"}'

curl -s 'http://192.168.0.10:8000/api/v1/calls'
```

Use a new event ID for each detection and reuse that ID only when retrying the same detection. To send a teacher-call test, use `"event_type":"TEACHER_CALL"`, `"severity":"DANGER"`, and a distinct event ID.

## Dashboard and Unity demo

1. Start the API, then open `http://127.0.0.1:8000/` in the director's browser.
2. Click **알림음 켜기** once; browser audio is enabled only after this user action.
3. In Unity, open the existing `ClassroomDemo` scene and set `AIConnector.baseUrl` to `http://127.0.0.1:8000` on the same Windows computer. For another computer, use the Windows LAN IPv4 address.
4. Post a `CRY_DETECTED` event using the ID returned by `/api/v1/demo/room`. Confirm the dashboard alert and yellow room floor. Accept it, start response, and complete it in the dashboard; the room returns to its normal floor color and the call shows completed.
5. Post a `TEACHER_CALL` event with a new ID to verify red. The demo room ID is not one of the real building-map rooms, so use **최근 호출 처리** for its lifecycle instead of implying a real map location.

Unity polls the existing `GET /api/v1/calls` every 1.5 seconds. It colors the matching loaded room only: cry warning is yellow, teacher call/danger is red, and no active event/completed status restores the original floor material. The room model uses the demo JSON dimensions and door placement; its simplified wall/window geometry is a visual demo, not an as-built survey. Furniture recognition from camera footage is outside this prototype. Event history currently resides in process memory and resets when the API restarts.

Real microphone detection, Mac-to-Windows LAN delivery, and browser audio on the makerthon machines require an on-site test; API tests alone do not verify those devices or the network.
